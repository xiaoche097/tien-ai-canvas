# 摹图接入境彻计划

## 目标和当前状态

用 `xiaoche0907/xc-aimutu` 的完整产品替换创意中心里的“电商设计室”，沿用摹图原有 UI 与工作流，共用境彻账号及可用模型。上游快照已放在 `apps/xc-aimutu/upstream/`；源码入口已指向 `/motu`，当前运行容器未更新，真实账号与模型的上线验收仍待完成。

成功标准：境彻登录用户可从创意中心进入摹图；看不到其他用户的项目和素材；所有生成请求使用境彻授权的模型、任务和计费链路；现有 web、后端及部署不因摹图不可用而失效；未来更新上游可看清上游变化与本地适配差异。

## 已核对的边界

| 位置 | 当前事实 | 接入要求 |
| --- | --- | --- |
| `web/`、根 Dockerfile、`nginx.conf` | Vite/React 静态站，`/api/` 代理 Go | Next.js 不能直接作为 Vite 页面导入；需独立构建和进程，不改变现有 web 的依赖树 |
| `apps/xc-aimutu/upstream/` | Next.js 14/React 18、Prisma/SQLite、本地文件、Electron/Remotion、约 60 个 API route | 保留原版 UI 和项目结构；服务器运行数据单独持久化，不把开发数据库纳入仓库 |
| 境彻 `/api/auth/session` | Go 用 HttpOnly、SameSite=Lax 的会话 Cookie，服务端解析当前用户 | 摹图服务端逐请求验证同一登录态；不能信任浏览器传来的用户 ID 或旧激活码 |
| 摹图 `listProjects`、`getProjectDetail` | 列表忽略激活码，按 ID 读取也没有所有权校验 | 项目、素材、任务、版本、导出及文件下载都必须按境彻用户检查归属；写路径在服务端强制校验 |
| 摹图 `FetchInterceptor`、`remote-auth` | 浏览器 localStorage 的激活码和独立额度服务 | 移除运行路径中的激活码、管理密钥与独立计费；不把境彻会话或模型密钥放入 URL/localStorage |
| 摹图 `ProviderAdapter`、配置页 | 自有 Provider、模型角色和密钥库 | 从境彻模型目录取得可用模型；文本/图片/编辑/视频调用境彻现有任务或系统模型链路，遵守权限、扣费及失败语义 |
| 上游路由 | 页面和 API 使用根路径 `/projects`、`/api`、`/settings` 等 | 选同源 `/motu` 前缀和 Next.js `basePath`，逐项处理普通 `fetch`、媒体 URL、跳转及下载的绝对路径；避免另建跨域登录机制 |

## 实施顺序与验证

1. **固定上游基线（已完成）**：记录 commit 和排除的运行数据。初次导入时除开发数据库外的 260 个上游追踪文件逐个与目标 commit 的 SHA-256 一致；随后接入代码已修改 `upstream/` 内的必要文件，今后同步须以该 commit 与当前工作树做三方比较。根 Docker 构建上下文已排除该目录。
2. **确定服务边界（隔离冒烟已通过）**：摹图使用独立 Next.js 服务和独立持久化目录，由同一 Nginx 的 `/motu` 代理到 Next；Next 配置 `basePath: "/motu"`。摹图页面、`/motu/_next`、`/motu/api`、上传及下载只进入 Next；境彻 `/api/` 与其他 SPA 路由保持原样。普通绝对路径请求已在浏览器入口重写，素材 URL 已加前缀。开发、本地、生产 Compose 均包含该服务；主 Web 不依赖其健康态启动。验证：隔离的正式 Next 与 Nginx 容器中，`/motu/` 经一次重定向返回 200，`/motu/api/projects` 和原 `/api/auth/session` 分别进入对应服务；真实境彻部署尚未验收。
3. **接入境彻身份和数据归属（模拟双账号冒烟已通过）**：同源浏览器请求携带境彻 HttpOnly Cookie；摹图服务端逐请求转发 Cookie 到内部 Go `/api/auth/session`，并以返回的用户 ID 将 SQLite 数据库和素材目录分别限定在用户目录。旧激活码、独立管理密钥及 Provider API 在接入模式下关闭。验证：隔离正式镜像中未登录项目 API 返回 401；模拟账号 A 创建的项目在 B 的列表中不可见，按 ID 读取返回 404；伪造用户请求头无法换身份；A 上传的素材仅 A 能读取。仍需真实境彻会话、退出和多账号验收。
4. **接入模型和费用（代码已接通，真实计费待验）**：文本及部分 OpenAI 兼容图片协议从境彻模型目录选择，经后端系统渠道代理走境彻鉴权和计费；摹图本地激活码扣费在接入模式下停用。隔离模拟目录和代理已跑通主图分析与图片生成。视频分镜、参考视频关键帧分析、场景图片已改用境彻文本/图片模型。合成流程上传场景图片到境彻资源库，再提交境彻时间线任务，完成后按账号下载到摹图历史视频；配音从境彻 OpenAI Audio 渠道生成，自定义 BGM 与画面转场在下载时用 ffmpeg 合成。后端时间线新增竖屏/方形尺寸，容器补齐 ffmpeg。真实视频模型、声音支持范围、计费、全流程和 Gemini 图片等协议仍待验收；缺少相应模型时明确返回错误，不切换入口。
5. **替换入口并验收（源码已切换，上线待验）**：创意中心卡片经原 `/projects/commerce-studio` 地址跳转 `/motu`，原电商设计室不再作为路由页面加载。开发、本地与生产 Compose、独立镜像发布及宿主更新器已纳入摹图服务。旧页面源码暂保留，以便验收期对照和回退；上线确认后再删除。验证：`web` 构建、摹图独立构建及真实路由验收；登录、账号切换、明暗主题、上传、生成、编辑、导出和回退路径通过。

## 合并和发布约束

- `upstream/` 已包含本地接入修改，不能视为干净上游快照。导入 commit 是更新基线；先比较基线、本地适配与新上游，再解决冲突并重跑验证。
- 上游自带两个大型 Remotion 图片数据源，合计约 46 MB；完整导入会增加仓库体积，但它们不进入现有 web 镜像构建上下文。后续同步时单独审阅这些文件的变化。
- 不把摹图的 `package-lock.json`、React 18、Next.js、Prisma 依赖装进 `web/`，也不改境彻的 Bun 锁文件。摹图有自己的构建及镜像。
- 不导入上游开发数据库、真实 `.env`、用户上传、生成结果或密钥。生产摹图数据放独立持久卷；宿主更新器在备份期间暂停摹图写入，将该卷加入 ZIP，回滚时恢复。首次从不含摹图的旧版本更新时没有历史摹图卷可备份。若新增/变更境彻数据库表，同步后端数据库专题文档。
- 入口源码已指向共用账号和模型的摹图服务；部署前仍须使用真实境彻账号、模型和账务完成验收。摹图服务故障不应阻止主 Web 启动；本版更新器拉取并校验摹图镜像 digest。首次从旧版更新时由旧更新器执行，摹图镜像会通过 Compose 的固定版本标签拉取，后续更新才使用本版的 digest 校验。
