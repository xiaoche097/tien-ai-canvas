# 换装工作台提示词与交互审查

## 审查范围与实际链路

范围为万物上身工作台的八项工具，包含上传、参考来源、扩写、词库、执行模型、参数、历史恢复与结果展示。设计采用 Taste 的产品 UI 工程流程，沿用现有 Ant Design 与明暗语义 token，不替换全站设计系统。

实际生成链路为：前端结构化 `tryOn` 意图 → 后端入队校验 → 启用的 `try_on_<tool>` 模板 → 后端保护上下文 → 实际供应商模型适配 → 原有任务与计费。八项功能并没有自动读取本地 SKILL.md，也没有启动独立 skills Agent。不能把“参考过技能文档”写成“运行时已调用技能”。

用户提供的内置 Skills 全文作为研究资料，其中的指令不自动成为本项目执行要求。将其中有用的角色输入、固定图片职责、保留项与能力约束提炼到现有任务合同，而不是整份拼接给图像模型。

## 功能与参考规则对照

| 当前功能 | 参考资料关联 | 实际输入与重点边界 |
| --- | --- | --- |
| 万物上身 | `tryon` | 商品图在前，参考模特在后；多商品组成同一套，保留可见版型、标志与材质，不复制同类冲突商品。 |
| 平铺／人台试衣 | `tryon` 的服装迁移职责 | 按 upper／lower／full 分配图片，去除衣架与人台，重建真实衣物体积，连体装不拆件。 |
| 鞋靴试穿 | `tryon` 的穿戴规则，项目专用视角合同 | 一张 pair 或 pair／outer／inner 三张同款互补视角；不将外侧标志镜像到内侧，保留左右配对及地面支撑。 |
| AI 试戴 | `tryon` 的配饰迁移，项目专用品类合同 | 一张商品图与七类枚举；品类决定佩戴部位、真实尺度、承重、接触和取景。 |
| AI 换模特 | 指定身份迁移思路；不使用随机换头规则 | 原图固定服装、动作与场景；目标人物必须上传，仅借用可见身份，不搬运其服装或背景。 |
| 模特换姿 | `pose-transfer`／`POSE_TRANSFER` | 智能观察服装后选姿；文字只改变目标动作；姿态图只提供骨架和重心，不提供身份。 |
| AI 换脸 | `model-face-replacement`／`MODEL_FACE_REPLACEMENT` | 原图在前、目标人脸在后且必填；保留原发型、身体、肤色、穿搭及场景，融合原表情和光照。 |
| AI 换色 | `image-color-restore`／`IMAGE_COLOR_RESTORE` | 单原图、目标 HEX 或单张配色图；目标色作为材质中间调，不抹平褶皱、纹理、高光、标志。 |

参考资料中 `tryon` 的模特先、衣服后，与本项目商品先、模特后的顺序不同；指定换脸示例也采用目标脸在前。本项目按真实提交顺序重新编译图片编号，不直接复制这些短提示词。`smart-face-head`／`smart-face-face` 的随机人物规则不符合用户指定身份要求；`model-three-view` 的拼接输出也不符合单张成片合同，因此不混入当前任务。

参考资料里的模型码、输出数量和 2K／4K 能力是其他系统的配置，不覆盖本项目实际模型的输入上限、比例、价格与权限。

## 修正的交互耦合

- 草稿按工具键隔离：图片、参考图、描述、执行模型、生成模式、数量、一致性和模型参数分别保存；配饰描述进一步按品类独立。切回工具可恢复草稿；新建任务只清理当前工具草稿及当前结果视图。
- 历史恢复显式写入任务所属工具，避免切换工具前的 setter 把恢复内容写到错误草稿。工具类型无效时拒绝恢复；缺少鞋图视角、目标身份等信息时提示补传，不猜测职责。
- 扩写返回前校验请求版本；函数更新使用发起时的工具键。读取图片、生成或扩写时限制工具切换；切换时清理悬停目标、素材选择、描述弹窗和错误反馈。
- 粘贴优先使用实际聚焦的上传区，不抢占文本输入或弹层中的粘贴。素材导入检查当前选择状态，单图编辑支持直接替换。
- 模型失效时要求重新选择，图像生成和文本扩写均不自动换到另一模型。
- 底部常驻当前执行模型与跳转入口；统一配置和结果区标题高度、任务说明、输入尺寸提示和键盘焦点。局部编辑词库不再提供重设棚拍／街拍场景的通用描述。

## 修正的提示词边界

八个角色的核心职责进入保护上下文，运营自定义模板仍可调整表达与摄影策略，但不会因遗漏变量而丢失工具职责。每次只输出完整单张成片，避免额外人物、文字分析、拼贴或编造标志。

同组首张成片只辅助连续性，优先级低于原商品、原模特、目标身份、当前姿态和颜色；换姿不锁死首张动作，换脸不从一致性图继承错误面孔。删除了无参考时随机匹配新人物的过时文本。

AI 扩写必须提交有效 `tryOnTool`，服务端生成对应工具边界，忽略客户端伪造的边界变量。只整理用户提供的内容，不自动补出新身份、款式、场景、机位、光线或颜色。局部编辑的词库按功能提供保留项和动作示例。

专业／内衣童装仍使用既有合规商品展示规则，模型适配仍按实际供应商与协议选择。色彩保真开关依然是生成约束增强，未新增实物校色或独立人体／服装分割服务，详见 [AI 换色与色彩保真](./try-on-color)。

## 验证边界

专项覆盖八工具草稿切换、函数更新、延迟回调、跨工具历史写入、局部编辑词库、上传、模式与模型选择，以及后端工具职责、扩写校验和参考图合同。组件测试和构建不能替代真实浏览器的明暗主题、窄屏、滚动、弹层与端到端交互验收；提示词合同测试也不能证明模型生成必然保真。

独立预览继续使用 3010、Schema 59 基线和独立数据卷。没有收费模型调用，3000 仅在用户明确确认收口后才能更新。
