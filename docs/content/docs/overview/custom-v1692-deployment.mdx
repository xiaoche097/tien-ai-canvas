# v1.6.9.2 定制版本构建与迁移

本分支保存 v1.6.9.2 定制前后端的源码基线，包含八项穿戴工具、上传及参考图模式、221 色色库、工具草稿隔离、提示词保护上下文及具体执行模型选择。模型选择器与创作输入区保留既有布局，不挂载会覆盖 Agent 的新增全局反馈悬浮按钮；反馈设置与管理收件箱仍保留。

## 构建入口

Web 使用根目录 `Dockerfile`，后端使用 `backend/Dockerfile`，均从仓库根目录构建。源码构建编排为 `docker-compose.local.yml`；其端口及挂载以该文件为准。服务器标准生产部署仍使用 `docker-compose.deploy.yml` 与配套安装流程，源码构建镜像不自动成为官方 Release，也不由官方 Host Updater 管理。

```bash
docker build --build-arg BUILD_VERSION=v1.6.9.2 -t open-ai-canvas-web:v1.6.9.2-custom -f Dockerfile .
docker build --build-arg BUILD_VERSION=v1.6.9.2 -t open-ai-canvas-backend:v1.6.9.2-custom -f backend/Dockerfile .
```

这些命令只构建镜像，不启动服务、不覆盖已有部署。全新实例必须独立配置数据卷、HTTPS、域名及模型渠道；真实密钥、数据库、上传素材及加密配置不随 Git 源码分发。现有实例升级应继续沿用实际 Compose 配置和正式数据卷，不应直接用仓库默认编排覆盖已有环境。

## 数据迁移

上游发布说明称没有 Schema 变化，但标签源码实际新增 Schema 60 `user_feedbacks`。后端与迁移程序均应从本分支构建；不能将旧的 Schema 59 迁移二进制留在新运行镜像中。

正式切换前检查活动任务并停服，备份数据库、业务资源及静态资源，在副本演练后通过相同镜像和正式配置执行 `migrate-schema up`、`migrate-schema verify`。不要把验收副本的数据写回正式环境。回退 Schema 59 时不能只换旧镜像，应在保留最新数据的前提下恢复匹配的更新前数据库及资源。

## 已执行验证与限制

Web 与后端镜像构建、前端类型检查、48 项专项测试及 588 项断言通过，覆盖穿戴工具、具体模型选择、Agent 历史跟随、音频波形及反馈。后端提示词、app、handler、repository、database 五包的换装、反馈、会话、Schema、迁移及代理字段专项通过。扩大的渠道检查有 21 项失败，与升级前构建的失败名称集合一致，尚未解决，不记作全量测试通过。

数据副本与正式数据的 Schema 60 迁移及完整性检查通过，关键业务表记录数与升级前备份一致。正式前后端健康，入口与就绪接口返回 200，入口静态资源可访问，匿名任务接口返回 401。没有执行自动化登录态浏览器回归或收费模型生成；Motu 未在本次升级中重建或重新验证。

更具体的穿戴功能与真彩还原边界见后端专题的 `try-on-audit.mdx`、`try-on-color.mdx`。真彩还原目前是生成约束增强，不代表已实现实物校色或输出色差校正。
