# Phase 1：隔离版本保存与恢复

## 本阶段范围

本次实现独立验收环境中的原文件保留、PSD/PNG 成对保存、不可变版本、幂等重试及恢复。仍只运行于 localhost:3002，不添加正式电商页面入口，不修改线上镜像、业务数据库或 schema，不合并 main。

Phase 0 的受控样本十步往返已由用户截图确认通过。Phase 1 的存储服务通过真实 SQLite 与磁盘测试；用户随后确认「可以打开也可以保存」，截图显示已打开隔离版本 v1，因此单版本保存与重新打开已获用户验收。多版本分支、断网重试和账号切换仍待确认，不把服务测试当成这些页面交互的验收。

## 模型与文件级变更

新增 `apps/xc-aimutu/upstream/lib/services/psd-refinement.ts`，使用既有 Prisma Client 类型与表：

| 既有实体 | 最小增量约定 |
| --- | --- |
| `ProductAsset`，REFERENCE | 源文件同时作为会话根；metadata 包含 psdSession、ownerId、sourceFormat、checksum、bytes。会话 ID 由来源请求标识生成，重复请求复用 |
| `ProductAsset`，EXPORTED | 每个版本一个 PSD 文件记录，metadata 标记 ownerId、sessionId、checksum、bytes |
| `ProductAsset`，GENERATED | 每个版本一个 PNG 预览记录，使用相同来源及校验元数据 |
| `SectionVersion` | 每次保存新建记录；imageAssetId 指向预览；promptSnapshot.psd 存 schemaVersion=1、sessionId、父版本、PSD/预览素材 ID、尺寸、两个 SHA-256、创建人和时间 |
| `PageSection.currentImageAssetId` | 本阶段不改写；正式模块预览切换属于 Phase 2 |

不增加第二套项目、素材或版本表。沿用 uploads / generated / exports 目录语义。每个新对象使用独立随机文件名，不覆盖原件或旧版本；版本号沿用该模块的 SectionVersion 编号。

新增 `psd-local-api.ts` 为 Vite 开发中间件；`psd-api.ts` 通过现有 `http` 访问 JSON、通过 `http.raw` 读取二进制。主产品 router 未注册这些实验接口。

## 运行边界与权限

- 登录态始终由现有 `localhost:3000/api/auth/session` 校验，转发浏览器已有 Cookie，不接收客户端自报用户 ID，不创建默认用户。请在 localhost:3000 登录，再使用 localhost:3002；两处主机名保持一致。
- 仅监听回环地址；写请求必须有允许的同源 Origin，不允许其他网站发起保存。匿名读取/写入返回 401，非同源写入返回 403。
- 按登录用户 ID 的 SHA-256 选择独立数据库和文件目录，复用电商现有的用户隔离方式。会话、版本和素材还检查 ownerId / createdBy；父版本必须属于同一会话。
- 数据目录为 `.local/project-workbench-debug/psd-refine/users/<scope>/`，迁移脚本仅初始化这里的新验收数据库，不读取或迁移正式商品数据库。
- 首次保存显式创建「PSD 隔离验收商品 / 精修验收模块」这组真实测试记录，使用既有 Project / PageSection。它是验收夹具，不是用户的正式商品，不向正式接口伪造商品或模块 ID。
- 单文件最多 50 MB，预览最多 6400 万像素；每用户隔离实验数据最多 1 GB。这是实验目录的固定保护额度，不扣减或冒充正式账号的存储账单。
- 当前中间件使用有大小上限的 multipart 内存解析，仅用于单进程本地验收；生产接入前应改为既有资源服务的流式/分片上传及正式配额。

## 保存与恢复语义

1. 浏览器通过本页导入文件或运行受控样本，保留原文件来源。仅在 Photopea 原生菜单打开、宿主不知道来源时，不能直接建立关联保存。
2. 首次保存上传原件并创建会话；接着串行导出 PSD 和 PNG。宿主打开的文档绑定临时 source 标识，导出前核对当前原生标签，拒绝将其他标签内容保存到该来源会话。导出期间宿主阻止编辑区域交互，避免两次导出之间手动编辑导致版本不一致。
3. 服务端校验大小、文件头、PSD 尺寸，并使用 Sharp 实际解码 PNG、核对尺寸。PSD 不在服务端执行，头部检查不等于完整 Photoshop 兼容性认证。
4. 文件写入后同步到磁盘并读回校验；两个素材记录和版本记录在同一数据库事务中提交。只有事务成功后页面显示「隔离版本已保存」。
5. 保存失败保留编辑器与已导出的内存快照。重试使用同一请求 ID、同一文件和同一父版本；请求 ID 对应不同内容返回 409。取消重试后才能导出最新编辑并发起新保存。
6. 数据库明确未提交时清理本次新对象；提交状态不明或数据库不可读时保留文件，避免误删已提交版本，允许同键重试确认结果。不重写旧版本。
7. 刷新页面后，左栏重新读取当前用户保存的会话及历史版本。读取版本文件时再检查所有权、路径和 SHA-256，成功后送入 Photopea。恢复旧版本后保存会创建以它为父版本的新分支。
8. 浏览版本列表不会改变当前文档的来源。用户切换账号或退出登录后重新聚焦页面时，清空旧账号编辑会话、下载链接和版本状态。
9. 关闭确认提供保存后关闭/重连；保存失败保留会话。编辑器内部脏状态仍使用保守提示，不声称可以精确感知全部原生编辑操作。

## 实验接口

所有 JSON 沿用 `{ code, data, msg, reason }` 信封：

| 路径 | 作用 |
| --- | --- |
| `GET /api/psd-lab/sessions` | 当前用户会话与用户 scope 标识 |
| `POST /api/psd-lab/sessions` | multipart 原件、格式、文件名、幂等请求 ID；创建测试商品内的会话 |
| `GET /api/psd-lab/sessions/:id/versions` | 当前会话版本 |
| `POST /api/psd-lab/sessions/:id/versions` | multipart PSD、PNG、请求 ID、可选父版本；成对持久化 |
| `GET /api/psd-lab/sessions/:id/versions/:versionId/psd` | 校验后返回授权 PSD 附件 |
| `GET /api/psd-lab/sessions/:id/versions/:versionId/png` | 校验后返回授权 PNG 附件 |

## 已执行检查

### 多版本、重试与账号切换补充

- 真实 SQLite 测试确认：提交已成功但回执丢失时保留已提交的两个文件；使用同一保存请求重试后只存在一条版本记录。
- 真实 SQLite 测试确认：保存 v1 / v2 后以 v1 为父版本另存，生成新分支，v1 / v2 不改写。
- 已知会话和版本 ID 也不能绕过用户校验读取 PSD 或 PNG；新增两种文件下载及版本列表拒绝测试。
- 修复账号切换后旧请求迟到回填的问题：识别切换/退出时取消网络请求和旧操作，在各个异步结果回填前校验所属账号；保存、恢复、文件导入、下载记录和验收回执均受保护。并行登录态查询仅采纳最新请求结果。
- 账号切换会清除旧文档、版本列表、下载链接、恢复确认框及成功提示；同账号的普通聚焦刷新不会取消进行中的操作。
- 上述重试测试模拟的是「事务已提交、回执丢失」，账号测试模拟的是迟到异步回执；不据此将真实浏览器断网/登录切换自动标为用户验收通过。

新增真实数据库/文件测试，覆盖：原件请求及并发保存幂等、两个文件与单一版本记录、已有模块预览不被改写、旧版本保留、父版本、重建数据库客户端后的恢复、跨用户读取拒绝、异会话父版本拒绝、同键不同内容拒绝、额度不足、事务失败回滚和文件补偿、PSD/PNG 尺寸不符及磁盘文件损坏拒绝恢复。

当前共 23 项专项测试、101 次断言通过，独立类型检查及构建通过，额外覆盖原生标签切换后的来源保护。实际实验 HTTP 检查确认匿名请求为 401、非同源写入为 403、伪造用户请求头仍为 401。测试里的 PSD 是受控头部夹具，PNG 是 Sharp 生成并真实解码的图片；这些测试不证明任意 PSD 能在 Photopea 中编辑。实际 Photopea 往返证据仍来自 Phase 0 用户截图。

## 浏览器验收步骤

首次使用时列表为空属于正常情况：Phase 0 的下载产物不会自动成为保存版本。空态提供「载入示例文件」，加载后再点击顶部「保存隔离版本」，出现成功提示后刷新并恢复。也可以直接导入自己的非敏感文件。

1. 在 localhost:3000 登录，然后刷新 localhost:3002。
2. 导入自己的非敏感图片/PSD，或运行已通过的十步样本。
3. 点击顶栏「保存隔离版本」，确认成功提示；继续编辑，再保存一个新版本。
4. 刷新页面，在左栏「隔离保存与恢复」选择会话，再打开 v1 / v2，确认尺寸、文字和图层正确。
5. 打开旧版本后保存，确认生成新版本而不覆盖旧版；检查正式商品预览没有变化。
6. 保存时临时断网，再恢复网络并点击「重试上次保存」，确认没有重复版本。
7. 退出登录或切换账号后返回，确认旧会话不可读、不能恢复旧账号文件。

- 生产多进程的并发控制/幂等确认；目前串行锁为单开发进程内，不能宣称具备跨进程事务协调。

- 实际商品/模块来源与源生成版本继承，并审查 JSON 增量合同对原有版本展示/激活的影响。
